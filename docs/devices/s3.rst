The S3 board
============

The primary target is the **Waveshare ESP32-S3-Touch-AMOLED-1.75**: a
1.75-inch round capacitive-touch AMOLED development board. It is the
whole product — the panel, the touch, the motion sensor, and the real-time
clock are all on the same small board, and the clock body (a 3-D-printed
stand holding the board and a battery, the panel render on the
:doc:`start page <../index>`) is mostly the board plus a
battery.

The whole product is one small board: the panel, the touch, the motion
sensor, and the real-time clock all share the ESP32-S3's QSPI, I²C, and
I²S buses. The schematic below traces those buses from the SoC to each
component and calls out the one wiring detail that constrains the sleep
machine — the RTC's alarm line never reaches a wake input.

.. graphviz:: ../_graphs/s3-wiring.dot
   :alt: S3 component wiring schematic
   :align: center
   :caption: The S3 board's component wiring — QSPI (CO5300 AMOLED), I²C (touch, IMU, TCA9554 expander, PCF85063A RTC), I²S (ES8311 codec).

The orange path is the wake-up caveat: the RTC's ALM output lands on the
TCA9554 expander's pin 3, which a running CPU polls at 1.3 s — it is
**not** wired to an ESP wake input, so a true ``esp_deep_sleep`` could
never be woken by a timer or alarm on this board. (The product's "deep
sleep" is app-level — the backlight off, the CPU still running — so the
alarm still fires via that poll. :doc:`The clock and sleep machine <../implementation/clock-sleep>`.)

SoC and memory
--------------

- **ESP32-S3**: dual-core Xtensa LX7, up to 240 MHz, with an FPU the
  bake uses (:doc:`the C core <../implementation/core-c>`).
- **16 MB flash** with an octal PSRAM. The flash is split by
  ``partitions.csv`` into a 2 MB ``factory`` app partition, a 64 KB
  SPIFFS ``storage`` (credentials + alarm rules), and a 2.5 MB
  ``moon_assets`` data partition that holds the equirect albedo and
  the int8 relief DEM (see :doc:`performance <../verification/performance>` for why the DEM's 2 MB size
  forced the 16 MB chip).
- **PSRAM caveat**: the S3's octal PSRAM is **not SPI-DMA-capable**.
  Every DMA transfer that the display stack performs must land in
  internal SRAM. This single fact shapes two things that look
  arbitrary until you know it: the LVGL flush strips are staged
  through internal RAM at 25 rows high (a 32 KiB S3 SPI DMA cap,
  :doc:`the display pipeline <../implementation/display>`), and the 2 MB relief DEM lives in PSRAM and is read by
  the CPU, never DMA'd.

The panel: CO5300 over QSPI
----------------------------

The **CO5300** controller drives a 466×466 RGB565 (5-6-5, no alpha)
AMOLED panel over **QSPI**. Two properties matter to the rest of these
docs:

- **No alpha channel.** The panel is either on with an RGB565 color or
  off; there is no per-pixel transparency. "Fading out" a screen means
  ramping the panel's *hardware brightness register* (register 0x51),
  not writing alpha. :doc:`The display pipeline <../implementation/display>` and :doc:`the clock and sleep machine <../implementation/clock-sleep>` both lean on this.
- **A brightness register, not a backlight PWM.** The CO5300 exposes a
  per-panel brightness value. The screen-switch "fade to black" and
  the light-sleep dim (:doc:`the clock and sleep machine <../implementation/clock-sleep>`) are both just slow writes to that
  register while the pixel content is held constant — which is also
  exactly why they are cheap and why a lost QSPI write shows up as a
  frozen frame, not a dimmed one (the GPSPI-stall incident,
  :doc:`on-device verification <../verification/device-verify>`).

Touch, motion, time
-------------------

- **CST9217** capacitive touch, I²C. The UI's indev layer polls it;
  the settings screens (:doc:`the round keyboard <../keyboard>`) and the clock-roll gesture
  (:doc:`the clock and sleep machine <../implementation/clock-sleep>`) both key off it.
- **QMI8658C** IMU (accelerometer + gyro), I²C. This drives two
  behaviors that are easy to miss in a photo: the **tilt wake**
  (departure from a settled pose wakes the device, :doc:`the clock and sleep machine <../implementation/clock-sleep>`) and
  the **clock roll** (the clock face counter-rotates to stay upright
  as you tilt the board, :doc:`the clock and sleep machine <../implementation/clock-sleep>`).
- **PCF85063A** RTC, behind a **TCA9554** IO expander, I²C. The RTC
  keeps the clock alive through light sleep, and because the product's
  "deep sleep" is app-level (the backlight off, the CPU still running)
  the alarm still fires from the dark screen. It fires by *polling*,
  not by a wake line: the PCF's ALM output is wired to the TCA9554
  expander's pin 3, and a running CPU reads that pin at 1.3 s intervals
  (the ``lv_timer`` interrupt handler). That line is **not** an ESP
  wake input, which is why the board could never be woken from a true
  ``esp_deep_sleep`` on a timer or alarm — the same fact the schematic
  above calls out. The alarm is armed through the RTC's hardware alarm
  (``clock_clear_alarm`` / re-arm — :doc:`the clock and sleep machine <../implementation/clock-sleep>` documents the "stale
  armed ALM fires a phantom alarm" bug that required disarming on a
  zero-rule boot).

Power
-----

The board is powered from USB in this build (the bench stand has a
coiled cable in the photos). The sleep machine (:doc:`the clock and sleep machine <../implementation/clock-sleep>`) exists
largely because an always-on AMOLED on a desk is a burn-in risk and a
power draw; light sleep keeps the panel on but dims it, deep sleep
turns the panel's backlight off entirely.

The custom shim
---------------

The board is driven through a vendored Waveshare BSP component
(``components/esp32_s3_touch_amoled_1_75``), but all the project's own
board logic sits in a thin shim, ``components/board``. The shim
(``board_display.c``) is deliberately small — it exists to give the
rest of the code one ``board_panel()`` and one
``board_io_expander_init()`` that behave identically on the S3 and the
P4 (the P4 has no IO expander and a different panel handle, so the
shim returns NULL / the P4 handle respectively):

.. code-block:: c
   :caption: components/board/board_display.c (the whole shim)

   #include "board_display.h"

   esp_lcd_panel_handle_t board_panel(void) {
   #if defined(CONFIG_BOARD_P4)
       return bsp_display_get_panel_handle();
   #else
       return bsp_display_get_panel();
   #endif
   }

   esp_io_expander_handle_t board_io_expander_init(void) {
       /* The P4 board has no IO expander (no PCF85063A interrupt line). */
   #if defined(CONFIG_BOARD_P4)
       return NULL;
   #else
       return bsp_io_expander_init();
   #endif
   }

The panel's DMA staging, the 25-row flush-strip limit, and the
``s_panel_mtx`` that serializes brightness writes are described where
they matter: the display pipeline (:doc:`the display pipeline <../implementation/display>`) and the sleep/dim
machinery (:doc:`the clock and sleep machine <../implementation/clock-sleep>`).

Building and flashing the S3
----------------------------

The S3 is the **default target**: a plain ``idf.py build`` (fresh
clone, no ``sdkconfig``) configures ``esp32s3`` from
``sdkconfig.defaults``. The full build + flash sequence
(:doc:`the board index <index>` for the shared conventions and the
port-identification procedure):

.. code-block:: bash
   :caption: The S3 target (``<port>`` = the identified port — run ``esptool.py --port <port> chip_id`` first)

   source ~/esp/esp-idf/export.sh

   # moon assets (local, gitignored; regenerate after touching the
   # asset pipeline or MOON_ALBEDO_W):
   cd assets/images/moon && .venv/bin/python -m moon.assets --target s3

   cd ../..
   idf.py build                          # default target = esp32s3
   # check the binary size against the 2048 K factory partition
   idf.py flash -p <port>                # app + storage SPIFFS + moon_assets
   idf.py monitor -p <port>              # serial console, 115200

Pre-configured defaults
-----------------------

The S3 build merges the shared defaults with
``sdkconfig.defaults.esp32s3`` (auto-appended for
``IDF_TARGET=esp32s3``, later file wins). The S3 file, in full:

.. code-block:: text
   :caption: sdkconfig.defaults.esp32s3 (the S3-specific values)

   CONFIG_IDF_TARGET="esp32s3"
   # Octal PSRAM at 80 MHz: the S3's in-package 8 MB.
   CONFIG_SPIRAM_MODE_OCT=y
   CONFIG_SPIRAM_SPEED_80M=y
   # The S3 core clock (the P4 runs at its own 400 MHz default).
   CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ_240=y
   # Task watchdog: core 1 runs the bounded moon bakes + the spin
   # render; a full bake can starve the CPU1 idle task for >5 s,
   # which would trip the (log-only) WDT. The bakes are bounded and
   # self-cancelling, so core 1's idle check is off; core 0's stays
   # on as the hang safety net.
   CONFIG_ESP_TASK_WDT_CHECK_IDLE_TASK_CPU1=n
   # LCD flush queue depth 1: the S3 SPI DMA caps one transfer at
   # 32 KiB and PSRAM is not DMA-capable, so every strip is staged
   # into internal RAM; depth 1 keeps the peak internal allocation
   # at one ~23 KB strip (deeper queues exhausted the heap).
   CONFIG_BSP_LCD_TRANS_QUEUE_DEPTH=1

**The board line asymmetry:** this file carries **no**
``CONFIG_BOARD_S3=y`` — the S3 is the *default* of the board
``choice`` (see below), so the default already selects it. The P4
file, by contrast, **does** carry ``CONFIG_BOARD_P4=y`` (overriding
the default back to the P4). The root ``CMakeLists``
target/board guard makes a stray board line in the wrong file a
build-time ``FATAL_ERROR``.

The shared file (``sdkconfig.defaults``) contributes the board-neutral
values: the 16 MB flash header (``CONFIG_ESPTOOLPY_FLASHSIZE_16MB=y``
— both boards flash a 16 MB header), ``CONFIG_PARTITION_TABLE_CUSTOM=y``
(the S3 keeps the default ``partitions.csv``), ``CONFIG_SPIRAM=y``,
the LVGL 9.6 setup (notably ``CONFIG_LV_USE_CLIB_MALLOC=y`` — the
clock-roll's full-screen PSRAM transform layer needs the libc
allocator, not LVGL's 64 KB static pool), and the UI seeds
(``CONFIG_UI_SCREEN_SWITCH_FADE=240``,
``CONFIG_UI_MOON_SPIN_SETTLED_PERIOD_S=600``,
``CONFIG_UI_MOON_SPIN_FPS=8``, ``CONFIG_UI_CLOCK_ALPHA_PCT=20``,
``CONFIG_UI_MOON_DUSK_ENABLE=y``,
``CONFIG_UI_MOON_ANIM_ON_WAKE=n`` — obsolete, kept for config
validation).
